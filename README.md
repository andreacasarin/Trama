# Trama

Trama is an Obsidian plugin for local AI conversation and semantic connections. Its V1 provides an agent chat, a local semantic note index, and SQLite-backed retrieval. Chat and search use providers only after explicit actions. After vault layout is ready, eligible indexing may also run automatically on startup, after Markdown changes, and on a five-minute backstop; it calls the configured provider only on cache misses. Loading settings itself remains offline.

Trama uses LangChain components for embeddings, Markdown splitting, agents, and tools. Each vault has a stable local index identity, and its SQLite database is stored in that vault's OPFS namespace. SQLite stores note metadata, chunk vectors, lexical search data, and a normalized note centroid. Search filters and ranks indexed data in SQLite; matching note content is loaded from the current vault when results are returned. The index does not persist raw Markdown bodies. Copying a vault's identity file copies its index namespace too.

On manual **Update index** or **Rebuild index**, and on eligible automatic Update runs, Trama imports compatible document embeddings before indexing and publishes immutable document-only SQLite files after indexing and cleanup succeed. Files are stored under `Trama/embedding-cache-v2/<profileHash>/<contentHash>.sqlite3`; they contain vectors and cache metadata, never note text, queries, chat, or attachments. Cache identity uses the trimmed model ID, embedding dimensions, and exact input, but not the endpoint address. Reuse across endpoints assumes the same model ID and dimensions produce the same weights; Trama does not verify weight equivalence. The files can be carried by the vault's ordinary file-sync service, while each device keeps its own SQLite index. If sharing is interrupted after indexing succeeds, already published files remain and Trama reports that sharing is incomplete; a later eligible automatic run or explicit update retries. There is no separate startup uploader; publication occurs within the indexing pipeline. Query embeddings stay local, with up to 1,000 entries per model/dimension profile for 30 days.

If indexing or cleanup fails or is cancelled, Trama publishes no cache files. If indexing and cleanup succeed but sharing is interrupted, completed immutable files remain and Trama reports “Index updated; sharing incomplete/cancelled.” A later eligible automatic run or explicit Update retries unfinished sharing; failed or cancelled runs do not restart immediately.

## Use

1. Install and enable Trama in Obsidian.
2. Configure an approved local OpenAI-compatible endpoint and embedding model before using provider-backed chat or semantic indexing. Settings loading remains offline; eligible automatic indexing may call the configured provider on cache misses. Lexical search does not require a provider call.
3. Run **Update index** to prepare the local index. Run **Rebuild index** when you want to replace it.
4. Use the available chat and search actions. Search results link to notes in the vault. With Page preview enabled, hover over Filo or Lente result titles to use Obsidian's native preview; configure Trama results in Page preview settings.

Manual Update/Rebuild remains available. After layout readiness, Trama makes one automatic attempt when eligible, coalesces relevant Markdown changes for about 20 seconds, and checks for missed changes or shared cache arrivals every five minutes. Automatic runs reuse the existing import, LangChain indexing, cleanup, and final shard-publication pipeline. They run only while the local note index contains notes; a fresh, cleared, or empty index stays paused across restarts until a manual Update/Rebuild produces notes. One pending event is coalesced during a run and followed only after success. Failure, Stop, Clear, or unload does not trigger an immediate restart, and unload cancels the pending debounce. Trama sends notes to LangChain in bounded batches of up to 100; each note is prepared before its atomic commit, and embeddings are flushed in bounded groups of up to 512 chunks. Full cleanup runs only after every input succeeds, including when the vault is empty. If indexing fails, the run stops and cleanup is skipped, leaving existing lexical data available. Changes made to notes during a run are picked up by the next successful manual or automatic update. Cancellation rolls back the active note transaction and keeps earlier completed commits. Related-note results persist locally across restarts and refresh after an index update when the active note is opened; this does not call a provider. Folder exclusions in settings are saved automatically and apply to selected folders and their descendants on the next successful update; existing indexed results remain until that update completes. Exclusions affect note indexing only and do not purge shared embedding-cache files or restrict attachments. Settings changes save automatically except when a local change to the effective embedding endpoint, model, or dimensions is made while an index exists or indexing is active: Trama asks before saving. Cancel keeps the settings and indexed data without stopping an active indexing run; Save changes saves the settings and recommends running **Clear index and embedding cache**, then manual Update/Rebuild. First configuration, an idle empty index, chat-only changes, and equivalent effective embedding settings do not prompt. Synced settings are retained and produce nonblocking advice only. Model ID and dimensions select the embedding-cache profile; the endpoint is excluded from cache identity, so reuse across endpoints assumes equal model IDs and dimensions have equal weights, which Trama does not verify. The optional Console debugging setting is off by default; when enabled, it logs concise operation timing, counts, and caught errors to the local developer console. When disabled, Trama emits no console diagnostics, including errors. All plugin settings, including model IDs and dimensions, are stored in data.json and follow Obsidian Sync's plugin-settings sync when enabled; Trama reloads external changes. Chat and embedding models each have one selector with an adjacent Discover control; choosing a model saves it. The reasoning effort selector offers Auto, None, Minimal, Low, Medium, High, and XHigh. Search results show each note's current modification date, and Lente/Filo show result counts with wrapped paths. Expanded details show Filo’s approximate, model-dependent **Similarity** rating. **Clear index and embedding cache** is available from Settings and the command palette. It clears the local index, document and query embeddings, cache import/publication receipts, and known managed SQLite cache files (including temporary files) under the vault's `Trama/embedding-cache-v2` folder across profiles. It leaves notes, settings, vault identity, the OPFS namespace, unrelated files, and other devices' local caches untouched. Shared files are removed through the vault's sync service; this does not guarantee copies have disappeared from other devices. Clear does not require a configured model. Rebuild and ordinary index reset retain caches. The SQL reset commits or rolls back before shared-file removal begins; cancellation before commit preserves prior local state, and file removal is not atomic. If removal is interrupted or fails after the local reset commits, Trama reports that the local index was cleared and shared-cache cleanup is incomplete, keeps automatic indexing paused, and allows Clear to be retried. A cleared or empty index stays paused until manual Update/Rebuild creates notes. A persistent notice reports Update, Rebuild, Clear, and Stop status. Voce offers the current note and up to five related notes as optional suggestions and never attaches them automatically.

The agent uses session-only conversation history and turn attachments. Tools are read-only and return note links. Provider calls disable response storage. When semantic retrieval cannot run, search falls back to lexical results and reports that it is degraded.

## Development

The packaged runtime consists of `main.js`, `sqlite-worker.mjs`, `sqlite3.mjs`, `sqlite3.wasm`, `manifest.json`, and `styles.css`. The repository includes a version hook and commands to build and install the plugin into the demo vault. The demo installer targets that vault only.

Use the current-app benchmark to compare repeated timing samples from the normal Obsidian plugin. Build and prepare the generated benchmark vault with `npm run build` and `npm run benchmark:prepare`, then follow [the Obsidian benchmark guide](docs/obsidian-benchmark.md). The comparison command is `npm run benchmark:compare -- before.json after.json`; it prints raw samples, medians, and after-minus-before milliseconds without writing files. Historical measurements and retired runner instructions remain in the [LangChain performance assessment](docs/langchain-performance-assessment.md).

The current implementation reference is [docs/langchain-sqlite-implementation.md](docs/langchain-sqlite-implementation.md). Historical design briefs, benchmark reports, and test inventories are labeled in their respective documents; they do not define current V1 behavior or performance claims.
