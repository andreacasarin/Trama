- The authoritative index is one Worker-owned SQLite WASM database. It uses FTS5 for lexical search, statically linked SQLite-Vector for exact cosine search, and the official OPFS SAH pool for persistence. Generated SQLite JS/WASM/manifests are not versioned; normal build/test materialize verified production assets from a fingerprinted cache built from pinned source/toolchain inputs. The normal plugin ships all required local assets; startup is network-silent, performs no runtime downloads, and does not perform model discovery, embedding, or other remote work. Legacy `.trama/index` data is never read, migrated, or used as fallback. Explicit closed snapshots are manual backups only, not publication, startup recovery, or automatic restore.
- Consistency is availability-first and eventually reconciled. A synchronization marks the index incomplete before searchable mutations and applies each note in its own atomic transaction; searches remain available and may observe mixed old/new notes or underfilled results. Per-note structural integrity is preserved: FTS rows, vectors, provenance, ordinals, and line bounds are updated together. A durable incomplete marker and monotonic change counter survive restart; later Update or Rebuild repeats reconciliation until the vault summary is stable and clears incomplete. Unchanged notes perform no writes or embeddings; modify embeds only that note; delete and rename never embed. Offline renames pair compatible path-independent content identities so stored vectors survive a path change.
- Retrieval is deterministic and shared across consumers: SQLite partitions note-shaped candidates before applying limits, combines lexical and semantic ranks with reciprocal-rank fusion, applies stable code-unit tie ordering, and returns fully hydrated provenance/evidence. FTS input is converted to safe bounded literal terms, never an interpolated expression. Filo uses stored vectors to compute the current note's chunk-vector centroid and performs semantic-only retrieval—no query embedding, FTS, or `queryTexts` cache.
- Preserve the durable user-facing Lente, Voce, and Filo contracts. Chunking remains provisional at 384 characters with 64-character overlap and one vector per chunk, without a tokenizer guarantee. Voce requests seven results. Filo overfetches 128 candidates, always shows the top seven unique notes, and extends to at most 20 only for additional notes with cosine similarity at least 0.30; its hydrated disclosure opens the note and expands the winning excerpt/line range without another lookup. View-owned similarity labels remain High at 0.72 or above, Medium at 0.50 or above, otherwise Low. Lente searches the committed visible-Markdown corpus, combines filename/path/body lexical fields with weights 3/2/1, supports explicit lexical-only fallback when query embedding fails, and keeps explicit-submit behavior; positive automatic-search delay is an opt-in debounce and Hybrid pauses may send a query to LM Studio. `Updated` is an explicit live-mtime reorder of bounded relevant candidates, never a hidden ranking boost.
- Base-readable Markdown is distinct from index eligibility. Trama owns a normalized, case-sensitive vault-relative exclusion list with exact-or-directory-boundary matching. Exclusions are corpus inputs: changing them requires Update or Rebuild, while Lente, Filo, and Voce do no query-time eligibility filtering. Explicit/open-note Voce access remains base-readable. Keyword Lente is offline; Discover, manual indexing, and Hybrid submission remain explicit user actions.
- Diagnostics stay privacy-preserving: the detailed debug stream is default-off, console-only, dynamically gated, and may report phase metadata and timings, but index/Filo diagnostics exclude note/chunk text, embedding inputs or vectors, content hashes, and serialized index data. Chat may carry sensitive payloads only with an explicit warning. Progress may expose structured phase-local state; transient UI settings can be snapshotted when a component opens, with saved changes taking effect on the next open unless a live contract requires otherwise. Prefer simple lifecycle semantics and avoid registries, rescheduling, or extra synchronization machinery without a demonstrated need.
- Tagged releases use `v*` tags whose versions match `package.json` and `manifest.json`; GitHub Actions publishes an exact six-file plugin zip containing `main.js`, `sqlite-worker.mjs`, `sqlite3.mjs`, `sqlite3.wasm`, `manifest.json`, and `styles.css`.
