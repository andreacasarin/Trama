- Trama’s semantic/RAG corpus is a single live mutable Orama 3.1.18 projection owned by `IndexManager` and `Retriever`. Its catalog fields include normalized path, content ID, public chunk ID, ordinal, line range, filename/path text, body, and embedding. Internal document IDs are reversible `JSON.stringify([normalizedPath, ordinal])` values; public content-addressed `chunkId`s remain separate. Exact-vector search, BM25, product reciprocal-rank fusion (`k=60`), and measured native 0.5/0.5 hybrid are first-class retrieval modes with deterministic ties and hydrated provenance. All Orama access uses package-root public APIs, every search requests `includeVectors: true`, and adapter receivers are preserved.
- Persistence is one completed `.trama/index.json` snapshot written only after a converged in-place Update or Rebuild. A runtime probe verifies same-directory overwrite semantics before publication, which then relies on one rename as a platform assumption rather than a generic or power-loss atomicity guarantee. The strict, versioned envelope records the fingerprint, dimensions, revision, catalog, and opaque public Orama save payload; readback and fresh public load validate the complete snapshot, catalog, and vectors. There are no generations, journal, previous/rollback, staging, migration, or old-backend compatibility paths. Sync mutates the live projection in deterministic batches, so partial mixed availability is accepted. Cancellation before replacement leaves dirty partial in-process state; once replacement begins, commit wins, the new snapshot is marked durable/clean, and the operation succeeds. Restart reads only the last completed snapshot; startup/readback rebuild a clean public projection from validated document-store entries and ignore stale temporary files. Startup is snapshot-load-only and network/embed silent. The legacy `.trama/index/` tree and unknown artifacts are never addressed or deleted.
- Synthetic scale evidence is an accepted limitation of this branch: responsiveness, memory, and storage warnings do not authorize workers, ANNFinder, or mobile-performance claims. Real-vault and desktop smoke testing remains user-only; all repository verification and benchmark data must be synthetic and sanitized.
- Chunking remains provisional at 384 characters with 64-character overlap and one vector per chunk, with no tokenizer guarantee. Chunk or backend changes require measured evidence and an explicit fingerprinted full reindex. Filo hydrates committed chunk vectors/catalog across restart, uses the chunk-vector centroid without query embedding or a `queryTexts` cache, and performs semantic-only retrieval. Candidate expansion is path-aware, so one note’s many chunks cannot prevent filling the requested unique-note set; it overfetches 128 candidates, always shows the top 7 unique notes, then extends up to 20 only for additional notes with cosine similarity >= 0.30. Voce still requests 7. Disclosure rows open notes from the title and expand the already-hydrated winning excerpt/line range without another lookup, with view-owned High >= 0.72 / Medium >= 0.50 / Low similarity labels.
- Full indexing derives a fast approximate embedding-text total from file-size metadata calibrated by a deterministic size-stratified sample of at most 32 notes through the real chunker. The estimate stays stable; if actual progress exceeds it, the UI becomes indeterminate, and the exact terminal count replaces the estimate. Filo presents one human-readable current-step row, a full-width progress bar, and a throughput ETA. Full and incremental indexing expose structured phase-local progress. **Update index** compares committed per-note content IDs, embeds only additions/changes, deletes missing notes, handles create/delete/rename, and makes an unchanged scan a no-op; **Rebuild index** is the forced full rebuild. Notes moved/deleted after discovery are metadata-logged and skipped, then queued rename/delete/create events reconcile them, including stale-modify-plus-rename ordering. Status/progress listeners dispatch over immutable snapshots; visible/hidden rename boundaries become create/delete operations; Voce refreshes and cache-validates on revision changes. Detailed debug is one global default-off, console-only, dynamically gated stream with metadata-only startup/load and Filo timings; chat may carry explicitly warned sensitive payloads, while index/Filo diagnostics exclude note/chunk text, embedding inputs/vectors, content hashes, and serialized index data.
- Lente is Trama’s third first-class native `ItemView` and search mode over the committed visible-Markdown corpus. It combines exact semantic and BM25 retrieval from the live projection, with filename/path/body weights 3/2/1, deterministic product RRF, and a winning passage per unique note. Query-embedding failures may explicitly degrade to lexical-only search. The sidebar is explicit-submit only; Search with Lente command-modal instances snapshot persisted `automaticSearchDelayMs` on creation, default to `0`/Enter-only, and debounce only when a positive delay is selected. `Updated` is explicit live-mtime ordering of bounded relevant candidates, never a hidden recency boost or persisted corpus metadata. Retrieval must not pass a vault-wide path set into Orama’s synchronous `where` clause, and Lente uses no private Obsidian core-search API, query grammar, or tag syntax.
- Base-readable Markdown is separate from index eligibility. Trama owns a normalized, case-sensitive, vault-relative path exclusion list with exact-or-directory-boundary matching. Exclusions are fingerprinted corpus input: excluded notes are omitted during indexing, changing the list invalidates the old snapshot and requires **Update index** or **Rebuild index**, and Lente/Filo/Voce perform no query-time eligibility filtering. Explicit/open-note Voce access remains base-readable. Vault changes remain queued for explicit **Update index**. Startup and Settings opening remain network-silent. Keyword Lente is offline; Discover, manual indexing, and Hybrid submission remain explicit user actions, with positive modal automatic-search delay an opt-in that can send Hybrid queries to LM Studio after pauses.
- Prefer simple lifecycle semantics: transient UI settings may be snapshotted when a component opens, with saved changes taking effect on the next open unless live updating is explicitly required; do not add registries, subscriptions, rescheduling, or other edge-case machinery without a demonstrated need, while preserving correctness where live synchronization is a stated contract.
