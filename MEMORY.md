- The authoritative semantic/RAG corpus uses schema-3 bounded paged manifests with actual UTF-8 byte budgets and deterministic code-unit ordering, plus immutable `TRAMASEG` binary segments, atomic current+previous pointers, per-note copy-on-write updates, pinned last-good snapshots, and root-bounds/generation cross-link validation. Eager segment validation enables current→previous startup fallback; GC validates every pointer/pin-retained segment, and activation requires an atomic rename and fails closed. The `DataAdapter` receiver must be preserved for every adapter call; startup performs zero network work and emits metadata-only phase timings when detailed debugging is enabled.
- Semantic retrieval is a custom contiguous normalized `Float32` exact-vector scan and permanent recall oracle with deterministic code-unit retrieval ties. Orama is a derived, nonpersisted, text-only BM25 index; Trama fuses semantic and lexical results with deterministic reciprocal-rank fusion (RRF) and hydrates committed provenance. Backend/framework types do not enter persisted artifacts or UI contracts; ANN requires benchmark evidence.
- Chunking remains provisional at 384 characters with 64-character overlap and one vector per chunk, with no tokenizer guarantee. Chunk or backend changes require measured evidence and an explicit fingerprinted full reindex. Filo hydrates from the corpus across restart, uses the committed chunk-vector centroid with no query embedding or `queryTexts` cache, and performs semantic-only retrieval so an active-note change never invokes Orama on the renderer thread. It overfetches 128 candidates, always shows the top 7 unique notes, then extends up to 20 only for additional notes with cosine similarity >= 0.30; Voce still requests 7. Its native-style disclosure rows open notes from the title, expand the already-hydrated winning excerpt and line range without another lookup, and classify cosine similarity with view-owned High >= 0.72 / Medium >= 0.50 / Low thresholds.
- Full indexing derives a fast approximate embedding-text total from file-size metadata calibrated by a deterministic size-stratified sample of at most 32 notes passed through the real chunker. The estimate remains stable; if actual progress exceeds it, the UI becomes indeterminate instead of moving the finish line, and the exact terminal count replaces the estimate. Filo presents one human-readable current-step row, a full-width progress bar, and a throughput-based ETA. Full and incremental indexing still expose structured phase-local progress for logs and lifecycle consumers. **Update index** is the normal synchronization pass: it compares committed per-note content IDs, embeds only additions/changes, deletes missing notes, and makes an unchanged scan a no-op; **Rebuild index** is the forced full rebuild. Notes moved/deleted after discovery are metadata-logged and skipped, then queued rename/delete/create events reconcile them without failing the operation, including stale-modify-plus-rename ordering. Status/progress listeners dispatch over an immutable snapshot, preventing settings resubscription recursion. Visible/hidden rename boundaries become create/delete operations, and Voce refreshes and cache-validates on generation changes. One global detailed-debug stream is default-off, console-only, dynamically gated, and includes startup/load and Filo phase timings; chat may carry explicitly warned sensitive payloads, while index/Filo diagnostics are metadata-only and must exclude note/chunk text, embedding inputs/vectors, content hashes, and serialized index data.
- Lente is Trama’s third first-class native `ItemView` and search mode: it searches the committed visible-Markdown corpus with exact semantic retrieval plus a derived, nonpersisted Orama BM25 index weighted across filename, path, and content, then groups results to unique notes with the winning passage. Query-embedding failures may explicitly degrade to lexical-only search. The Lente sidebar remains explicit-submit only; Search with Lente command-modal instances snapshot persisted `automaticSearchDelayMs` on creation, default to `0`/Enter-only, and use a positive delay to debounce after the last keystroke. Default ranking is deterministic relevance, while `Updated` is an explicit live-mtime reordering of bounded relevant candidates—never a hidden recency boost or persisted corpus metadata. Retrieval must not pass a vault-wide path set into Orama's synchronous `where` clause; at 2,740 paths that filter blocks the renderer for tens of seconds. Lente uses no private Obsidian core-search API, query grammar, or tag syntax.
- Base-readable Markdown is separate from index eligibility. Trama owns a normalized, case-sensitive, vault-relative path exclusion list with exact-or-directory-boundary matching. Exclusions are a fingerprinted corpus input: excluded notes are omitted during indexing, changing the list invalidates the old index and requires **Update index** or **Rebuild index**, and Lente/Filo/Voce perform no query-time eligibility filtering. Explicit/open-note Voce access remains base-readable. Background index reconciliation is disabled until derived-index updates are incremental or moved off the renderer thread; vault changes remain queued and require **Update index**. Startup and Settings opening remain network-silent. Keyword Lente is offline; Discover, manual indexing, and Hybrid submission remain explicit user actions, with positive modal automatic-search delay an explicit opt-in that can send Hybrid queries to LM Studio after pauses.
- Prefer simple lifecycle semantics: transient UI settings may be snapshotted when a component opens, with saved changes taking effect on the next open unless live updating is explicitly required; do not add registries, subscriptions, rescheduling, or other edge-case machinery without a demonstrated need, while preserving correctness where live synchronization is a stated contract.
