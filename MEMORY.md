- The authoritative index is one Worker-owned SQLite WASM database persisted by the official OPFS SAH pool. Lexical notes, chunks, provenance, and FTS5 are authoritative independently of optional `chunk_vectors`, which store normalized Float32 vectors for exact SQLite-Vector cosine search. Mobile and desktop share the Worker/WASM/OPFS runtime and packaged assets; startup and settings loading are network-silent, with no runtime downloads, model discovery, embedding, or other remote work. Legacy `.trama/index` data is never read, migrated, or used as fallback.
- The database has two identities: `corpusFingerprint` covers schema/extraction/chunk parameters and normalized effective exclusions (including the publication directory), while `embeddingFingerprint` covers the synchronized embedding configuration and vector space. Endpoint identity is excluded from the corpus identity but included in embedding-space identity. Lexical and semantic are logical channels over the same SQLite database, with one status contract (`unavailable | empty | partial | ready | incompatible`, independent `idle | updating` activity, and `searchable`); partial lexical rows remain searchable, while semantic search requires complete compatible coverage. Changing corpus settings requires lexical Update/Rebuild; changing embedding settings invalidates vector compatibility without deleting lexical rows.
- Consistency is availability-first and eventually reconciled. Update and Rebuild are zero-network lexical reconciliation: each note is applied in its own atomic transaction, FTS rows, chunks, provenance, and obsolete-vector deletion remain structurally consistent, and searches may observe mixed old/new notes or underfilled results until convergence. Unchanged chunks retain compatible vectors; changed or deleted chunks cannot retain stale vectors. A durable incomplete marker and monotonic change counter survive restart, and later lexical reconciliation clears incomplete when the vault summary is stable. Explicit semantic Prepare is the only enrichment path: it requests missing/incompatible chunks in bounded batches, validates and resumes compatible vectors, and leaves committed batches and lexical search usable on failure or cancellation.
- Retrieval is deterministic and shared across consumers: SQLite partitions note-shaped candidates before limits, combines lexical and semantic ranks with reciprocal-rank fusion, applies stable code-unit tie ordering, and returns hydrated provenance/evidence. FTS input is converted to safe bounded literal terms, never an interpolated expression. Hybrid uses RRF only when query embedding succeeds and compatible vector coverage is complete; otherwise it returns lexical results with an explicit fallback/status reason. Filo is semantic-only and requires complete compatible stored-vector coverage; it uses the current note’s chunk-vector centroid and never query embedding, FTS, or `queryTexts` cache. Voce’s search tool can use lexical retrieval, while sending Voce still requires chat capability/security behavior.
- Preserve the durable user-facing Lente, Voce, and Filo contracts. Chunking remains provisional at 384 characters with 64-character overlap and one vector per chunk, without a tokenizer guarantee. Voce requests seven results. Filo overfetches 128 candidates, always shows the top seven unique notes, and extends to at most 20 only for additional notes with cosine similarity at least 0.30; its hydrated disclosure opens the note and expands the winning excerpt/line range without another lookup. Similarity labels remain High at 0.72 or above, Medium at 0.50 or above, otherwise Low. Lente searches committed visible-Markdown SQLite FTS with filename/path/body weights 3/2/1, supports explicit lexical-only fallback when query embedding fails, and keeps explicit-submit behavior. Positive automatic-search delay is opt-in debounce; Hybrid pauses may send a query to LM Studio. `Updated` is explicit live-mtime reorder, never a hidden ranking boost.
- Base-readable Markdown is distinct from index eligibility. Trama owns a normalized, case-sensitive vault-relative exclusion list with exact-or-directory-boundary matching; exclusions are corpus inputs and take effect through Update or Rebuild, while query consumers do no query-time eligibility filtering. The active publication directory is excluded automatically without changing the displayed user list. Keyword Lente is offline; Discover, manual indexing, semantic Prepare, and Hybrid submission remain explicit user actions.
- Cross-device sync publishes one fixed, self-describing synchronized artifact: configurable directory default `Trama/index`, exact path `<publicationDirectory>/index.sqlite3`. The sync provider is the last-writer-wins authority; Trama adopts a differing valid publication only by equality of opaque `publicationId`, with no timestamps, hashes/manifests, publisher/device ordering, clocks, compression, chunking, merge, or conflict catalog. Publication blocks local index writes and adoption through copy, stage/readback SQLite validation, shared-file replacement, and finalizing the same ID in the live DB; validation/adoption keeps one operation-scoped backup for rollback. No reconcile or republish occurs on adoption, and successful converged lexical Build/Update/Rebuild or semantic Prepare auto-publishes. A publication failure does not roll back the successful local index; retry makes a fresh copy without rebuilding. The single-writer operating assumption is to wait for sync convergence before another device indexes; all settings sync, including endpoints.
- Diagnostics stay privacy-preserving: index, Filo, and publication diagnostics are metadata-only; detailed debug is default-off, console-only, dynamically gated, and may report phases, timings, byte sizes, and transient copy/resource measurements, but excludes note/chunk text, embeddings, content hashes, and serialized index data. Explicitly enabled chat diagnostics may include prompts, selected note contents, raw responses/SSE/tool payloads, and must show a UI warning. Expose both channel statuses, publication/adoption failures, and snapshot-loaded/not-locally-reconciled freshness distinctly. Preserve simple lifecycle semantics; avoid registries, rescheduling, or extra synchronization machinery without demonstrated need. Tagged releases use `v*` versions matching `package.json` and `manifest.json`, with the exact packaged runtime assets required for offline desktop/mobile operation.
