- TalaDB `0.11.3` is the sole production embedded corpus/search backend. It runs behind a Worker with locally bundled Worker/glue/WASM assets; production storage uses the native DataAdapter receiver. The native browser path is validated through the representative 25k-chunk profile; 50k is unsupported after Worker/WASM unreachable and a prior ~1.93 GiB restart failure, while 100k is unrun, so scale above 25k requires new evidence or optimization. Tala portable metadata and checkpoints live under `.trama/index/taladb-v1/**`. Legacy schema-3/TRAMASEG/CorpusStore/Orama/exact production implementations are removed; old `.trama/index` artifacts are inert, unread, and unmigrated. Backend/framework types do not enter persisted artifacts or UI contracts. Startup/load and settings opening stay network-silent and never embed.
- The index is one mutable availability-first store. Individual writes are durable/ACID; Update and Rebuild mutate it in place while searches continue and may observe partial, stale, duplicate, or mixed results. Ready/dirty status is explicit; an interrupted mutation remains searchable but dirty, and a later Update/Rebuild converges it. There is no atomic generation swap, current/previous publication, or automatic rollback. Explicit snapshots are portable checkpoints only, not per-update publication or recovery. Preserve the DataAdapter receiver on every adapter call.
- Semantic retrieval is flat exact cosine with deterministic Trama code-unit tie ordering, reciprocal-rank fusion (RRF), and provenance hydration. BM25 is Tala FTS with explicit body, filename, and path channels and weights. Tala native hybrid is benchmark-only; use it in production only after measured evidence. Chunking remains provisional at 384 characters with 64-character overlap and one vector per chunk; chunk/backend changes require measured evidence and an explicit fingerprinted full reindex.
- Filo hydrates from the corpus across restart, uses the committed chunk-vector centroid, performs no query embedding and keeps no `queryTexts` cache, and remains semantic-only. It overfetches 128 candidates, always shows the top 7 unique notes, then extends to at most 20 only for additional notes with cosine similarity >= 0.30; Voce still requests 7. Disclosure rows open notes from the title and expand the already hydrated winning excerpt/line range without another lookup. View-owned cosine labels are High >= 0.72, Medium >= 0.50, then Low.
- Full indexing estimates embedding-text work from file-size metadata calibrated by a deterministic size-stratified sample of at most 32 notes through the real chunker. The estimate stays stable; if actual progress exceeds it, the UI becomes indeterminate, and the exact terminal count replaces the estimate. Filo presents one human-readable current-step row, a full-width progress bar, and throughput ETA; full and incremental indexing expose structured phase-local progress for logs/lifecycle consumers. Update index is normal synchronization: compare committed per-note content IDs, embed additions/changes, delete missing notes, and make unchanged scans no-ops. Rebuild index forces a full rebuild. Notes moved/deleted after discovery are metadata-logged and skipped, then queued rename/delete/create events reconcile them without failing the operation, including stale-modify-plus-rename ordering. Status/progress listeners dispatch immutable snapshots. Visible/hidden rename boundaries are create/delete operations; Voce refreshes and cache-validates when the mutable-index generation changes.
- Lente is Trama's third first-class native `ItemView` and search mode over the committed visible-Markdown corpus. It uses exact semantic retrieval plus Tala FTS BM25, weighted across filename, path, and body/content, then groups to unique notes with the winning passage. Query-embedding failure may explicitly degrade to lexical-only search. The sidebar is explicit-submit only; Search with Lente modal instances snapshot persisted `automaticSearchDelayMs` on creation, default to `0`/Enter-only, and debounce after the last keystroke only when a positive delay is configured. Ranking defaults to deterministic relevance; Updated is explicit live-mtime ordering of bounded relevant candidates, never a hidden recency boost or persisted corpus metadata. Do not pass a vault-wide path set into Tala's synchronous filter. Lente uses no private Obsidian core-search API, query grammar, or tag syntax.
- Base-readable Markdown is separate from index eligibility. Trama owns a normalized, case-sensitive, vault-relative exclusion list with exact-or-directory-boundary matching. Exclusions are fingerprinted corpus input: excluded notes are omitted from indexing, a changed list invalidates the old index and requires Update or Rebuild, and Lente/Filo/Voce perform no query-time eligibility filtering. Explicit/open-note Voce access remains base-readable. Background reconciliation may run off the renderer in the Worker; its startup policy still never embeds, while vault changes may remain queued until Update when reconciliation is unavailable. Keyword Lente is offline; Discover, manual indexing, and Hybrid submission remain explicit actions, and positive modal automatic-search delay explicitly opts into sending Hybrid queries to LM Studio after pauses.
- Prefer simple lifecycle semantics: transient UI settings may be snapshotted when a component opens, with saved changes taking effect on the next open unless live updating is an explicit contract. Do not add registries, subscriptions, rescheduling, or edge-case machinery without demonstrated need; preserve correctness where live synchronization is required. One global detailed-debug stream is default-off, console-only, dynamically gated, and may include startup/load and Filo timings. Chat may carry explicitly warned sensitive payloads; index/Filo diagnostics are metadata-only and exclude note/chunk text, embedding inputs/vectors, content hashes, and serialized index data.
