# 2026-09-29 — Keep evidence separate from presentation

I decided the demo notebook and benchmark corpus should live in different vaults. The benchmark needs fixed inputs and output checks; the demo needs readable prose that we can keep improving.

[[Deterministic benchmark fixtures]] explains why a friendly collection of forty notes is not a replacement for the stable workload. Changing a title for a screenshot should not invalidate a performance comparison.

The same principle helps with tests. [[Refactoring-resistant tests]] protects observable behavior rather than the current helper structure. I still want narrow checks for risks that a happy-path lifecycle cannot expose, especially stale results and validation boundaries.

Next: give the presentation vault a memorable name, Trama Test Vault. Keep its content fictional and its provider settings independent. I want to be able to open it confidently during a call without exposing personal notes or wondering which environment a command is targeting.
