# 2026-09-24 — Provider boundaries

I want to be precise about what “local-first” means in this demo. Notes live in the vault and the index is local, but model inputs go to whichever endpoint the user configures. A remote endpoint is still remote.

[[Local-first AI]] should make that distinction visible. The benefit is control over the boundary, not a blanket promise that no text can ever leave the device.

For a live presentation, I will configure models in this test vault rather than copy settings from another vault. I also want keyword search available when no embedding model is selected. That gives a simple first interaction before introducing inference.

Open question: how much provider setup belongs in the public walkthrough? Probably a brief prerequisite, with the main sequence focused on notes. [[Embedding model identity]] is the right place for the compatibility details, not the opening slide.
