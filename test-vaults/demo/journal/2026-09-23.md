# 2026-09-23 — Markdown is structured input

The note about chunking was too abstract, so I rewrote it around the boundaries people actually create: headings, paragraphs, and complete code blocks.

Markdown is not just a string to cut into equal pieces. A heading can explain what a paragraph means. A list can record a decision. Splitting those structures carelessly may make a passage harder to retrieve or understand.

[[Chunking preserves useful context]] now states the tradeoff without claiming there is one perfect chunk size. Short notes already provide useful boundaries, which is another reason to keep the demo Zettelkasten concise.

I need to remember that changing chunking changes behavior as well as performance. The benchmark output expectations should not quietly move just because a new implementation creates different passages.
