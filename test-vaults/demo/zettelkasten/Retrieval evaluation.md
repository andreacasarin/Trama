# Retrieval evaluation

A retrieval evaluation begins with a question and a defensible expectation about relevant notes. It should include exact terminology, paraphrases, and questions that connect more than one topic.

Performance and relevance are separate observations. A query can be fast and wrong, or accurate and unnecessarily expensive. Recording both prevents an optimization from quietly becoming a behavior change.

The demo notebook provides human-readable examples, but it is not a frozen benchmark. I expect to improve its prose, add links, and change presentation over time. The stable workload remains elsewhere, with versioned inputs and independently pinned outputs.
