# Test vaults

These committed inputs are development material, not production plugin files. The demo and benchmark sources are not CLI targets. Run benchmark mutations only in the marked generated vault under `.artifacts/test-vaults/`.

- `demo/`: fictional notes for interactive walkthroughs.
- `benchmark/trama-small/`: 24-note smoke and correctness fixture. Preserve these committed files; the 3,000-note benchmark corpus is generated by `npm run benchmark:prepare`.

Build the plugin and prepare the generated vault:

```sh
npm run build
npm run benchmark:prepare
```

The preparer creates or reuses `.artifacts/test-vaults/benchmark/Trama Benchmark Vault`, marked with `.trama-benchmark-vault`. It restores a missing generated note on rerun and never overwrites existing content. It installs the built plugin and enables Trama in that vault. It does not open or register the vault; open the exact generated path in Obsidian yourself. Do not use a personal vault.

The corpus has SHA-256 `66d061b6c61c157587bf1dace04c6e72e7b0c5d3f8dd44393699d3b50f7b1c8a`. The current-app procedure uses manual Rebuild, Lente hybrid search, unchanged Update, one-note delete/update, preparer restore, and Update. It records existing Console Debug timings for three repeated cycles after an unmeasured warm cycle. See the [current benchmark guide](../docs/obsidian-benchmark.md) for the procedure, expected counts, report format, and comparison command.

See [demo setup](../docs/demo-vault.md) for the interactive walkthrough.
